本轮只把执行方案与名单落地，没有替你完成上述调查。45家D包只是已有业务依据的细筛候选，开始前按旧限制逐家公司放行。53家含8家POTENTIAL，这8家先观察/定向补缺；不因已采用分类就全部进入财务预测。

局部推进：某包5家中3家证据通过，3家可进入下一步，另2家留HOLD。新建F财务包和I拐点包时只使用通过名单，分别最多5/3家；数据未形成前不提前塞满后续包。包间依赖记录在package_index，不靠聊天记忆。

每个结果先REVIEW_PENDING。验收者另存review.json（包ID、逐公司结论、核读证据、采用限制、验收人、日期、SELF_CHECK或独立复核）。更新任务状态和主表必须基于此记录。启动状态NOT_STARTED/IN_PROGRESS/BLOCKED/REVIEW_PENDING/ACCEPTED_WITH_LIMITS/DONE；筛选结论与执行状态是不同列。

建议每天只开1个新包；人工补件可以同时进行。每次结束留下已完成、待补、未做、下一步四项。按包推进，不给1054家设虚假的完成日期。


## 每包新增归档检查

每份实际采用的原件登记document_id、官方URL、Drive真实file ID/链接及版本。archive_status区分NOT_UPLOADED / UPLOADED_UNVERIFIED / VERIFIED；access_check_status区分NOT_CHECKED / OWNER_ONLY_CHECKED / AI_READ_CONFIRMED / ACCESS_BLOCKED，两者分别填写。

只有AI实际取得并核读原文才可记AI_READ_CONFIRMED；用户打开Drive文件成功只记OWNER_ONLY_CHECKED。来源不可读的公司保持HOLD，不强制等待全库迁移才做其他有原文的公司。Google Drive未配置与资料未归档属于存储缺口，不等于公司无业务。

交接写明本包引用的document_id、Drive URL及仍需上传/授权读取的资料。GitHub不存大附件，本地交接ZIP默认只放索引；需要直接附件时仅附本包必要原件。


## 资料归档放行门槛（按分级规则 v1.1）

- 全体候选公司只需维护L1来源索引，不做全池预下载。
- 实际用于分类/业务判断/财务计算的文件必须纳入L2：优先官方完整PDF，Drive文件ID/URL真实登记，上传后回读核对。不能下载/上传的，保留具体阻塞并标REVIEW_PENDING/HOLD，不冒充归档完成。
- 影响结论的证据必须达到L3：document_id、PDF物理页、短原句、主体、事实发生时间、披露时间、事实/计划性质和限制均可追溯。
- 归档状态和AI读取状态分别验收；AI必须读到完整原文才可写AI_READ_CONFIRMED。归档失败不会自动判为没有业务，也不必阻塞其他已有合格原文的公司局部推进。
