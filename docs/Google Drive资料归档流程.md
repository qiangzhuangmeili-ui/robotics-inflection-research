# Google Drive 原文归档流程

研究信息截止日仍为 2026-10-24。Drive项目主目录、5个分类目录和首包交接目录已创建并核验；已在Drive定位72份PDF，64份原去重资料与8份新增年报；其中7份旧批补件和威贸电子已核读正文身份。旧64份仅核对元数据，云端哈希/正式公告来源/版本仍待逐项复验。真实链接和本地逐文件路径见[本地PDF上传位置清单](本地PDF上传位置清单.md)。

## 文件分别放在哪里

| 位置 | 保存内容 | 用途 |
|---|---|---|
| GitHub 私有仓库 | 来源登记、公告网页原始链接、Drive 文件链接/ID、PDF页码、短引文、关键数字、研究结论和待核问题 | 记住结论从哪里来，方便逐包推进 |
| Google Drive | 年报、中报、公告 PDF，扫描件，以及较大的原始 Excel/ZIP | 留存可重复查阅的原始资料，避免把大文件塞入 GitHub |
| 电脑的 `sources/` 或 `inbox/` | 下载中、等待核对或临时交给 AI 的副本 | 临时中转；确认 Drive 归档后才考虑清理重复副本 |

GitHub 中的短引文要足以识别它支持的事实，但不能代替完整上下文。每条关键证据都要同时登记真实公告网址和实际 Drive 文件链接/ID；报告标题、披露日、报告期、PDF 物理页码、描述主体和事实发生时间一并保留。

## Drive 文件夹怎么摆

主目录和5个分类目录已在你的 Google Drive 创建，见[data/drive_folders.csv](../data/drive_folders.csv)。旧64份资料的公司/报告期子目录已随上传建立并可通过实际文件定位；新增7份补件直接位于对应公司文件夹，威贸电子年报位于2025年度子文件夹。下面是标准归档结构：

```text
机器人行业拐点研究/
├── 01_原始资料/
│   └── 六位代码_公司简称/
│       └── 报告期/
├── 02_批次交接/
│   └── 包ID/
├── 03_历史版本/
├── 04_财务与数据导出/
└── 05_行业资料/
```

例如，一家公司 2025 年年报 PDF 放在 `01_原始资料/证券代码_公司简称/2025年度/`；真正交给 AI 的压缩包或临时整理文件放在对应 `02_批次交接/包ID/`。更正公告或修订版作为新文件放在原报告期文件夹或 `03_历史版本/`，两版都保留，并在登记表写清哪版先发、哪版更正，不能覆盖旧原件。

## 人工上传：照着做

1. 打开已建立的[项目主目录](https://drive.google.com/drive/folders/1v8RYlfohKcrGrulwCFq3fZSnGdjFxUYQ)；现有72份原件已能定位，请先查[data/document_registry.csv](../data/document_registry.csv)，不要重复上传。未来新PDF才按[本地上传清单](本地PDF上传位置清单.md)参考位置归档，不要重复建立同名主目录。后续新增公司时再按上面结构建子目录。Google 的按钮名称会随页面调整；官方电脑端说明目前是点左上角“新建”再选“文件上传”或“文件夹上传”。
2. 上传正式公告 PDF。文件名可以保留网站下载的原名；如果不好辨认，可在副本名中加证券代码、公司简称和报告期。不要改 PDF 内容。
3. 在 Drive 中找到上传后的文件，确认文件能打开，标题、报告期和修订版本正确。把原网页 URL、Drive URL、Drive 文件 ID、文件原名、存放文件夹及核对状态记入统一索引 `data/document_registry.csv`；当前包可从 `templates/来源登记.csv` 复制一份到自己的 `results/` 作为来源表，并引用同一 `document_id`，不要把空白模板当结果覆盖。ID 和 URL 从实际文件链接/元数据取得；不要自己拼造。
4. 对同一份原文只归档一次。先按证券代码、标题、报告期和来源 URL 查索引；已存在时，把现有 Drive 文件 ID 链到证据登记中，不重复上传。不同报告或不同更正版本各自登记。
5. 文件“可以在你的账号打开”只表示你自己已核对。需要 AI 读取时，要确认对应 Google Drive 已连接到当前 AI，并让 AI 通过 Drive 搜索/实际文件 ID 读取，再回报它读到的报告标题、日期和目标页。连接无权限或没读到 PDF 原文，就把状态记为 `ACCESS_BLOCKED`，转附件或 `HOLD` 补件；不要让它根据摘要写成“已读原文”。
6. Drive 已核对并且登记完整后，才清理本机重复缓存。删除前先确认 Drive 中确有正确报告且能打开；不要删掉唯一原件。下载中的文件、未核实的重复和待人工处理资料继续留在本机 `sources/` 或 `inbox/`。

上传步骤可参照[Google 官方的文件上传说明](https://support.google.com/drive/answer/2424368?hl=zh-CN)。复制链接时保留“常规访问权限”为“受限”，不要为了让 AI 读取而改成“知道链接的任何人”。Google 说明，受限文件只能由已获授权的账号打开；共享父文件夹也会影响下层文件的权限。因此“我能打开”不等于“AI连接的账号能打开”。需要调整访问时，先使用 AI 产品已经连接的授权流程，或改为当前对话附件；不要擅自扩大文件共享范围。[Google Drive 官方共享和权限说明](https://support.google.com/drive/answer/7166529?hl=zh-CN)

## 登记状态怎么填

`archive_status` 描述“文件有没有归档并经人工核对”；`access_check_status` 描述“指定读取方能不能实际读到”。两列分开，避免把“我上传成功”误认为 AI 已经读过：

| 字段 | 含义 |
|---|---|
| `NOT_UPLOADED` | 尚未归档到 Drive |
| `UPLOADED_UNVERIFIED` | 已上传，但还未核对文件名、报告期、版本和可打开状态 |
| `VERIFIED` | 人工确认 Drive 中的文件对应登记的原件且可打开 |
| `NOT_CHECKED` | 还没有实际尝试让当前 AI 读取 |
| `OWNER_ONLY_CHECKED` | 只确认你自己的 Drive 账号能打开 |
| `AI_READ_CONFIRMED` | 当前 AI 确实读到 PDF 原文，并能说出报告身份和你指定页面内容 |
| `ACCESS_BLOCKED` | 当前读取方没有权限、没有连上 Drive，或只得到链接/摘要而没有读取原文 |

AI 读取检查最好让它复述一个指定物理页的标题或关键句，再由你在 PDF 中对照。写在聊天里的链接本身不能证明 AI 有访问权限。

## 交给 AI 时怎么说

告诉它包 ID、证券代码和 Drive 文件 ID/链接，并要求先查连接的 Drive，核对元数据和权限，再打开 PDF 原文。让 AI 回复“读到的文件标题、报告期间、指定页码及短引文”，最后把确认结果写回来源登记。若当前 AI 没有可用的 Drive 连接，手动把该 PDF 作为聊天附件上传。两种方式都不能读取时，写清缺什么文件并设 `HOLD`；不要猜内容，也不要公开 Drive 文件。
