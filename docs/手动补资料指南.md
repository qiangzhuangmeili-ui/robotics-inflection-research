## 先准备公司信息

从当前包的 `assignment.csv` 复制证券代码和简称。代码要保留六位，包括开头的 `0`；不能只凭相似的公司简称认定找对了公司。查到网页后，再对照证券代码、上市公司全称和报告年份。

## 去哪里找正式报告

优先使用公司正式披露的原文：

1. [巨潮资讯网](https://www.cninfo.com.cn/)：用六位证券代码或简称查公司，进入对应公司后搜索“2025年年度报告”“2026年半年度报告”或任务指定的公告标题。注意分清“年度报告”“摘要”“更正公告”等不同文件；需要支持业务判断时，尽量打开报告全文 PDF。
2. [上海证券交易所信息披露](https://www.sse.com.cn/disclosure/listedinfo/announcement/)：适用于上交所上市证券。可用证券代码或简称搜索；也可以从[定期报告预约情况](https://www.sse.com.cn/disclosure/listedinfo/periodic/)定位正式披露日期，再打开对应公告。
3. [深圳证券交易所信息披露](https://www.szse.cn/disclosure/index/index.html)：适用于深交所上市证券。用证券代码、简称和报告年份查找对应公司公告。
4. [北京证券交易所上市公司公告](https://www.bse.cn/disclosure/announcement.html)：适用于北交所上市证券。用证券代码或简称搜索正式公告。
5. 公司官网的“投资者关系/投资者关系活动/公司公告”页面可以补充正式材料。仍要核对发布公司和日期；不要拿新闻转载或搜索摘要代替公告原文。

每个网站的搜索框和按钮位置可能变化。找不到页面时，回到官网首页再找栏目；不要为追求速度下载不明来源的“报告副本”。

## 下载后怎么放、怎么登记

1. 下载后的原始 PDF 和大文件优先放进你自己的 [Google Drive 归档结构](Google%20Drive资料归档流程.md)。电脑的 `sources/` 和 `inbox/` 可作临时下载、待核对或附件中转目录；它们不是云端 AI 可自动读取的路径。
2. 保留官网下载的原文件名和内容。按“证券代码_公司简称/报告期”放入 Drive。更正版作为另一份新文件登记，别覆盖原版；同一份报告只存一份，通过 Drive 文件 ID 让多条证据引用它。
3. 在统一索引 `data/document_registry.csv` 登记证券代码和公司名、官方公告标题、官方网页 URL、Drive URL/文件 ID、文件名、报告期、披露日、版本和存放目录。当前包从 `templates/来源登记.csv` 复制一份到自己的 `results/`，沿用同一 `document_id`；页码和短原句填证据表，归档状态与 AI 是否实际读到分别填写。不要覆盖空白模板。Drive 链接只从真实文件的“复制链接”操作取得，ID 不要猜。
4. 重要判断的短引文、PDF 物理页、关键数字和结论记录在 GitHub 的证据表。原文 PDF、扫描图和较大的 Excel/ZIP 文件放 Drive；GitHub 只留追溯信息，避免保存大量附件。
5. 在 PDF 阅读器里确认原文。可以用 WPS PDF、Adobe Acrobat Reader 或浏览器自带 PDF 阅读器；不需要为本任务新安装软件。用 `Ctrl+F` 搜索“机器人”“人形”“智能制造”“订单”等词只是定位，仍要读命中句前后的段落和表格。
6. 记录**PDF 文件物理页码**（从 PDF 第 1 页往后数）。如果报告纸面页码不同，可以两个都记上；找不到印刷页码时留空，不猜。
7. 只抄支持结论所需的短句，保持原文措辞。把已发生事实和未来计划/预测分开，并记清事实发生时间、公告披露时间，以及描述的是母公司、并表子公司还是参股公司。
8. 清理本机重复副本前，先确认 Drive 中正确版本能打开且来源登记已完成。不能删唯一原件；如果你能打开但 AI 还没读过，`archive_status` 可以是 `VERIFIED`，而 `access_check_status` 仍要填 `OWNER_ONLY_CHECKED` 或 `NOT_CHECKED`。

## PDF 打不开、AI 找不到路径时

- 连续查找一份资料约 **15 分钟**仍没有进展，就先停。把已经试过的网址、页面提示/错误、公司代码和仍需找的文件写进 `data/manual_requests.csv`。如果该表还没有明确的列，先保留已有列，并在一条记录里写清：代码、公司全名、所需资料、试过的官方网址、失败情况、你手上是否已有文件。不要因为下载失败就记成“公司没有机器人业务”。
- 只有自动下载/上传确实受阻时，才由用户下载并上传到归档清单指定的Drive文件夹；如果目标文件已由用户放入Drive，AI应重新搜索并回读核验，不再要求二次上传。下载成功但 AI 不能读取本机文件时，使用聊天窗口的“添加附件/上传文件”把 PDF 直接交给 AI。需要一起提供时，将**本批的** `TASK.md`、`assignment.csv`、来源登记表和对应 PDF 压缩成一个 ZIP 再上传。上传前打开 ZIP 看一眼，确认没有把整个电脑文件夹、其他公司的材料、密码或私人文件一起打包。
- 本机 `robotics-inflection-research/deliveries/` 已准备好 67 个单包 ZIP，第一份校准包是 `C00_PILOT_01.zip`，可以直接作为 AI 附件。ZIP 默认不含 PDF；你另外下载原文后，再把 PDF 一起附上即可。`deliveries/` 不上传 GitHub，所以从 GitHub 下载的整库 ZIP 不包含这些本机单包附件，也不是同一种 ZIP。
- PDF 较大或不想重复上传时，优先把原件留在你的 Drive，把真实 Drive 文件 ID/链接写入来源登记。当前 AI 已连到 Drive 且有文件权限时，可以让它按登记检索、读文件元数据并打开 PDF 原文；你在浏览器里能打开不代表 AI 也能打开。权限受限或连接不可用时，请把 PDF 作为附件交给 AI；仍读不到就记录 `ACCESS_BLOCKED` 并将该公司留在 `HOLD`。不要为省步骤改成公开链接，也不要把摘要冒充 PDF 原文。
- 只把 `D:\某目录\文件.pdf` 这种路径发给云端 AI 不会自动上传文件。先用已登记的 Drive 真实链接和已连接的读取工具；仍无法读取再附文件本身，路径只用于你在电脑上找到它。
- 如果 PDF 是扫描图片、不能搜索或某页看不清，记下页码和问题；可以把相关页面单独截图后作为附件提供。不要凭模糊文字或 OCR 结果猜数字。
- 网址、附件或任务本身仍不清楚时，把问题登记到求助表，让后续安排明确补什么。不要自行替换名单、把未知改成 0，或改用未经核验的新闻来“补齐”。

## 本地研究工具箱能帮什么

仓库内保留了工具箱的旧版说明：[工具箱说明](../archive/toolbox_guide.md)。其中列出的本机工具箱页面是 `http://127.0.0.1:8774/toolbox`；只有你已经启动原有本地研究服务时，这个页面才可能在你自己的电脑上打开。云端 AI 不能访问你电脑上的 `127.0.0.1`。本指南不代表该页面现在正在运行；如果浏览器打不开，就先跳过，不要为了这份研究安装新软件。

工具箱可以帮助查询部分结构化行情、财务和公告信息；它返回公告链接时，仍要点击并核对正式报告原文。**有公告链接不等于完整 PDF 已经下载。** 工具箱的任务结果可下载为 ZIP，但 ZIP 里的数据不能自动代替官方原文和页码核对。
