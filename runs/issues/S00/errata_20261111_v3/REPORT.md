## 二、V3 与 V2 的根本差异：重述核验改按 document_id 匹配

**这是我 V2 最严重的错误，也是 Codex 要求「按公司、期间、document_id 对账」时我漏掉的一项。**

证据链：

1. `tools/s00_restatement_apply.py` 第 36 行 `verdict[r["document_id"]] = r["verdict"]`、第 46 行 `v = verdict.get(r["document_id"])`——**回填只按 document_id 应用，完全不看期间**。
2. `restatement_verify/results.csv` 是 **1,007 文档 / 1,007 记录**，1:1，零重复。
3. 一份报告可以供给多个期间：2025 年报的「分季度主要财务数据」同时供给 20250331/0630/0930 的单季值，资产负债表比较列供给 20251231。核验表把该年报登记在其中一个期间名下（多为 20250630）。

V2 按（公司, 期间）匹配，导致**同一文档供给的其它期间全部落空**，5,073 条被误判为「未覆盖」。按行取 `document_id` 后：

| 分类 | 条数 |
|---|---:|
| 文档级判定与 B 一致（真已解决） | 5,149 |
| 方法为假设（WEAK，仍计未闭合） | 515 |
| 供给文档从未核验（真未覆盖） | 26 |
| 文档判定与 B 相反（真冲突） | 4 |
| 合计（原 V2 未闭合重述） | 5,694 |

**这直接改变下游结论：HOLD 从 17 家降到 14 家。**

其中 **大豪科技** 需要单独说明：V2 判 `STILL_PASSES_WITHOUT`，理由是 `REV.SQ@20250331` 有重述争议。V3 查实该行的供给文档是 2025 年报（`DOC-58344807D745035C`），核验判定「否」，与 B 标记一致——**争议真解除**，故改判 `NOT_AFFECTED`。V2 的「改判」本身建立在按期间取文档、被同期间其它字段覆盖的错误上。
