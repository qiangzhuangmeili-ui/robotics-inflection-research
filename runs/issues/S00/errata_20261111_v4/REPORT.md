## 二、V4 与 V3 的根本差异：文档定位 ≠ 证据适用范围

Codex 的核心批评是：应用脚本的广播范围不是核验证据的适用范围。一条 `IMPORTANT_MATTER_NA` 记录只说明「该报告未披露重大会计差错更正」，不能推出「该报告供给的所有期间、字段、比较列都未发生追溯调整」。

V4 因此把重述处置拆成三态：

| 处置 | 条件 | 条数 |
|---|---|---:|
| `RESOLVED_RESTATEMENT_OWN_PERIOD` | 行期间 = 文档自身期间，verdict 等于 B，方法非假设 | 15,316 |
| `PENDING_SCOPE_AUDIT` | 行期间 ≠ 文档自身期间（取自比较列/分季度表），须核追溯调整范围 | **1,148** |
| `PENDING_WEAK_ASSUMPTION` | 方法为 `ASSUMED_NO_PENDING_REVIEW` | **515** |
| `UNRESOLVED_DOC_NEVER_VERIFIED` | 供给文档不在 1,007 份清单 | 26 |
| `UNRESOLVED_EVIDENCE_MISMATCH` | verdict 与 B 相反 | 20 |
| `UNRESOLVED_NO_EVIDENCE` / `FIELD_NOT_IN_RECORD` / `RECORD_IS_REMOVE` | 其他元数据 | 349 |

**待核不计已闭合。** 这是 V4 与 V3 最大的口径差别：V3 把 5,149 条直接算「已解决」，V4 只承认 15,316 条（行期间=文档自身期间），1,148 条转入待范围对账。
