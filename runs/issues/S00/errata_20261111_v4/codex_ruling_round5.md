## 二、A：期间相等不能替代证据适用范围核验

`build_errata_v4.py:284–310` 的实际逻辑是：

> 文档核验记录存在、非假设、verdict 等于 B，且行期间等于文档自身期间，即判已解决。

**这一充分条件不成立。**

期间相等只说明日期对应，不能证明核验记录覆盖了该字段、表格、调整原因及派生输入。报告自身期间的单季值也可能由本期和前季累计值差分；“重大会计差错更正不适用”同样不能因期间相等而自动覆盖其他调整原因。

脚本虽然在第 38 行定义了 `SCOPE_LIMITED_METHODS`，但实际判定分支未使用它限制自动闭合。

对 15,316 条 `RESOLVED_RESTATEMENT_OWN_PERIOD` 复算：

| 核验方法 | 条数 |
|---|---:|
| NOTE_TRACE_NA | 9,950 |
| IMPORTANT_MATTER_NA | 4,707 |
| NOTE_RETAINED_ERRATA_ZERO | 563 |
| SUPP_NEG | 67 |
| NOTE_TRACE_NOT_OCCURRED | 29 |

其中仅后两类既有重点受限方法 `IMPORTANT_MATTER_NA`、`NOTE_RETAINED_ERRATA_ZERO`，就有 **5,270 条、297 个文档**因“期间相等”被自动放行。它们应重新检查适用范围，不能继续整体计作已证据闭合。

例如 `meta_diff.csv:51`，奥美森 `FIN.AR.INSTANT@20250630` 的依据仍只是重大会计差错更正“不适用”，并未展示为何该依据覆盖本字段的全部调整风险。

其余方法也应按实际证据内容分组审查，不能仅凭方法名称整体认可或整体否决。

**更合适的判据是：实际证据是否覆盖该断言。** 至少绑定：

- 主体、文档身份及版本；
- 表格、物理页、行列和字段；
- 数值所属期间及比较基准；
- 调整原因和适用范围；
- 直接提取或派生关系，以及必要父输入。

## 五、D：1,273 格暂挂合理，232 格整体归展示不成立

### 1,273 格

在未完成字段核验前，列为待核是合理的；**不能把待核理解为字段错误，也不能不分用途全部阻断。**

字段级标准应分类：

| 字段类型 | 核验要求 |
|---|---|
| 数值、单位、币种、版本 | 记录覆盖字段及操作，终值或规范化转换结果与 B 一致 |
| HOLD、资格、低基数等 | 核变更理由、对应规则，以及是否影响本次资格 |
| 期间、来源、发布日期 | 核文档身份、所属期间、真实披露时点及版本采用 |
| 自由文本 | 核内容是否完整、准确表达证据和限制，以及是否遗漏决定资格的信息 |
| 派生输入 | 核实际父输入、公式、期间及版本一致性 |

“自由文本没有终值相等可言”不准确。文本仍有终值，可以核对记录；只是**字符串相等不足以证明内容正确**。没有预定终值时，应留下内容审查及采用理由。
