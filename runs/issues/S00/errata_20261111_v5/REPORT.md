**日期**：2026-11-12　**上游裁决**：`codex_ruling_round5.md`（第五轮，RETURN_FOR_REWORK）

## 一、这一版改了什么

第五轮裁决的核心不是数字错，而是**判据错**。V4 用「行期间 == 文档自身期间」当作「该行未被重述」的充分条件；裁决第二节指出这不成立——期间相等只说明日期对得上，不能证明核验记录覆盖了该字段、该表格、该调整原因和派生输入。

V5 因此换了判据，不是加补丁：

| 维度 | V4 | V5 |
|---|---|---|
| 重述闭合判据 | 行期间 == 文档自身期间 | 证据实际覆盖范围 ⊇ 该行断言必需范围 |
| 覆盖范围来源 | 方法名整体认可 | 从证据正文抽取（`evidence_scope.coverage_of`） |
| 必需范围来源 | 无 | 按 B 的实际取值状态（`required_scope`） |
| 受限方法 | 定义了 `SCOPE_LIMITED_METHODS` 但未使用 | 强制待核 |
| 依赖展开 | 统一字段映射 | 读 B 的实际 status |
| 补充元数据 | 232 格归「溯源/展示」 | 四类实质字段，全部字段级待核 |
| 差异追溯 | 多标签拼一个 `dispute_id` | 每条差异一个稳定 ID，绑定台账版本 |

### 1.1 新判据的两个函数

`evidence_scope.py` 把「证据覆盖了什么」和「这行需要什么」分开算：

- `coverage_of(rec)`：从证据正文抽 `ERRATA` / `MERGER_RETRO` / `POLICY_CHANGE` / `QUANTIFIED`。
  例：`NOTE_RETAINED_ERRATA_ZERO` 的正文是「重大会计差错更正影响期初未分配利润 0.00 元；同一控制合并范围变更 0.00 元」——它同时覆盖差错更正与同一控制合并，比方法名看起来强。
- `required_scope(status, own_period)`：
  - 非自身期间（比较列 / 分季度表供给别的期间）→ `ERRATA + MERGER_RETRO + COMPARATIVE_SCOPE`
  - `EXTRACTED_QUARTERLY_TABLE` → `ERRATA + QUARTERLY_TABLE_PROVENANCE`
  - 其余 → `ERRATA`

差集写进 `scope_missing`，逐条可查。

**为什么没给累计差分行加 `MERGER_RETRO`**：同一份报告内 YTD 相减，两个父输入受同一次追溯调整影响，差分后相互抵消；真正的风险是「父输入是否可信」，那属于依赖引擎的职责。若在这里加，会把「同一份报告内相减」也判成证据不足，正是裁决第三节警告的过度传播。所以改成依赖侧单独检查（见 1.3）。

### 1.2 5,270 条受限方法转待核

`IMPORTANT_MATTER_NA`、`NOTE_RETAINED_ERRATA_ZERO` 两类方法只覆盖「重大会计差错更正」一节，且不绑定字段/表格/行列。V5 一律不自动闭合：

- 自身期间 **5,270 条**（与裁决复算数完全一致）
- 非自身期间 1,103 条（V4 本就待核）
- 合计 `PENDING_SCOPE_LIMITED_METHOD` **6,373 条**

其中 `NOTE_RETAINED_ERRATA_ZERO` 的 563 条证据已量化 0.00 元，属**可优先复核组**——但不是已闭合。

### 1.3 依赖引擎改读实际行状态

`l2_core.expand()` 现在按 B 的 `status` 分支：

| status | 展开 |
|---|---|
| `EXTRACTED_QUARTERLY_TABLE` | 只依赖自身，不加累计父键 |
| `DERIVED_Q1_EQUALS_YTD` 或日历 Q1 | 加 YTD(t)，不减上年年末 |
| `DERIVED_CUMULATIVE_DIFF` | 加 YTD(t) 与 YTD(t−1q) |
| 状态未知 | 并集（保守，供自检与故障注入） |

裁决点名的例子已修：

```
dependency_keys("M07", "20260630")
→ 含 FIN.NPDEDT.YTD@20250331   （V4 缺这一条）
```

`check_l2_v5.py` 按公司注入真实 status，因此不再出现「直接分季度表被强加累计依赖」和「Q1 减上年年末」。

### 1.4 232 格不再整体归展示

原「溯源/展示」桶清零，四类字段各自立类：

| 字段 | 格数 | 新类别 | 依据 |
|---|---:|---|---|
| `evidence_label` | 85 | AFFECTS_ADOPTION_EXPLANATION | 采用解释（国机通用新增仲裁标签） |
| `source_page` | 78 | AFFECTS_TRACE_LOCATION | 证据定位（同方股份 61→137） |
| `slot_id` | 43 | AFFECTS_PROVENANCE | 供给槽位（q1_2025→annual_2025） |
| `status_reason` | 26 | AFFECTS_QUALIFICATION_REASON | 资格理由 |

实测这 232 格中 **191 格同时改了 document_id 或 period_source**，41 格虽同文档同来源但页码/理由文本变了。没有任何一格能凭列名免检。

### 1.5 受限表改为逐条追溯

- `dispute_id` = `sha1(台账版本|台账|公司|字段|期间|元数据字段|方向)[:12]`，每条差异一个稳定 ID
- 新增 `dispute_ledger.csv`（9,312 条唯一差异）
- 受限表新增 `dispute_ids`（分号列表）、`dispute_count`、`ledger_version`、`ledger_sha256`、`status_B`
- 292 行受限声明绑定 281 个唯一差异 ID，无未映射 ID

## 二、结果

### 2.1 台账总量不变，分类重排

| 台账 | 行数 | V4 未闭合 | V5 未闭合/待核 |
|---|---:|---:|---:|
| 值差异 | 240 | 34 | 34 |
| 键差异 | 2,056 | 405 | 405 |
| 核心元数据 | 17,728 | 2,057 | 7,360 |
| **核心小计** | 20,024 | **2,496** | **7,799** |
| 补充元数据 | 1,505 | 1,273 | 1,505 |
| **合计** | 21,529 | **3,769** | **9,304** |

核心 2,496 → 7,799（+5,303）。分解：5,270 条受限方法自身期间重开 + 33 条其他标签重分类（`PENDING_SOURCE_PROVENANCE` 48 与原有待核合并后的净变化）。

裁决给的阶段算术是 2,497 + 5,270 = 7,767。V5 的 7,799 比它多 32 条，差额来自标签合并的净变化（原 1,147 条 `PENDING_SCOPE_AUDIT` 在新判据下拆成 48 条 `PENDING_SOURCE_PROVENANCE` + 若干条受限方法待核，另有 8 条 `NOTE_RETAINED_ERRATA_NONZERO` 因 B=是 判为 `RESOLVED_RESTATEMENT_CONFIRMED`）。**这不是最终未闭合数**，其余方法仍待分类审查。

### 2.2 重述差异：62 个同质分组

17,009 条重述差异按「方法 × 覆盖签名 × 取值来源 × 是否自身期间」分成 62 组，供逐组复核（`summary.json:meta_diff.restatement_groups`）。前几组：
