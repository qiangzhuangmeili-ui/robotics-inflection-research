## 一、第七轮裁决的逐条落实

第七轮认可了期间参数、稳定 ID、逐表哈希与故障注入数字，退回返工的是三处实现缺陷和三条自检绕过路径。

### 1.1 A 项：必需范围改为「期间要求 ∪ 来源要求」

V6 的 `required_scope` 在非自身/未知期间分支直接 `return`，把 status 本来要求的来源维度覆盖掉了：
非自身期间的分季度表行不再要求 `QUARTERLY_TABLE_PROVENANCE`，非自身期间的累计差分行不再要求
`PARENT_COMPATIBILITY`。当前因比较范围仍缺而未立即误放行，但补证后会形成漏洞。

改为 `period_scope(期间) | source_scope(status, 行期间)`，两者互不替代。新增 **C36** 双向验：
四个合成断言 + 全量非自身期间分季度表行逐行核「两维是否同时存在」。

**直接后果**：8 条 `PENDING_CONFIRMED_EVENT_FIELD_OPEN` 的 `scope_missing` 由 `COMPARATIVE_SCOPE`
变为 `COMPARATIVE_SCOPE;QUARTERLY_TABLE_PROVENANCE`——与第七轮 D 项的判断一致。

### 1.2 B 项：极性重写

第七轮在内存复现了三个误放行：

| 输入证据 | V6 结果 | V7 处理 |
|---|---|---|
| `前期差错更正\n√适用□不适用` | `EXCLUDED`（看到「不适用」就排除） | 解析勾选符号：√ 打在「适用」上 → `AFFIRMED` |
| `本期发生前期差错更正，但会计政策变更不适用` | 两种原因都被排除 | 否定只绑定最近的 `POLICY_CHANGE` |
| `未发生前期差错更正。本期发生前期差错更正100.00元` | 仍可解除 | 记 `conflict=ERRATA` → `UNRESOLVED_POLARITY_CONFLICT` |

另三处一并修：

- **事件与影响分离**：「差错更正对期初未分配利润影响 100.00 元」同时记 `affirmed=ERRATA`（事件已确认）
  与 `scoped=ERRATA`（影响只限该权益项目），新增 `PENDING_EVENT_CONFIRMED_SCOPE_LIMITED`。
- **纯标签行不判极性**：「追溯重述法」是小节标题，不再被当成肯定；否则它与下一句「未发生」构成假冲突。
- **冲突阻断范围**：只有「本行必需排除的原因」冲突才阻断。`POLICY_CHANGE` 自相矛盾不影响
  「未被差错更正」这条断言——首版未区分，误阻断 152 行。

C34 从 4 个反例扩到 **9 个**，全部来自第七轮点名的输入或本次修法的边界。

### 1.3 C 项：父输入兼容性重做

V6 的判据有四个漏洞，第七轮逐个点名：

| 漏洞 | V7 处理 |
|---|---|
| 文档相同不证明调整额相同 | 保留（同文档 = 同一报告口径，两者已被同一次调整改写，差分有效） |
| `version_used` 同为 `ORIGINAL` 不证明同一调整版本 | **撤销该分支** |
| 任一父键在采用审计中不证明另一父键兼容 | **改为两个父键都必须有采用记录且 `document_id_after` 相同** |
| 空的范围/币种/单位字段相等不算已确认一致 | **改为必须非空且一致** |

跨文档情形新增两条正面判据：两份文档都判定「未被重述」（同为原始口径），或两个父键都已采用同一修订文档。

**Q1 按单个累计父输入处理**：`DERIVED_Q1_EQUALS_YTD` 与所有 `pk` 以 `0331` 结尾的行不再要求
`PARENT_COMPATIBILITY`——Q1 单季就等于 Q1 累计，没有相减，套两期相减是错的。

**重开结果**：`PENDING_PARENT_COMPATIBILITY` 5 → **1,277**；父输入兼容 YES 3,566 → **4**。
第七轮指出「1,272 条靠相同 `version_used` 分支通过」，重开数量与之一致（1,277 含自身期间新判定）。

### 1.4 D 项：事件确认不再用方法名兜底

`bval == "是"` 分支原先允许 `method == NOTE_RETAINED_ERRATA_NONZERO` 作为事件已确认的兜底，
等于把方法名当原文证明。现改为**只认原文极性** `ERRATA in affirmed`。

8 条确认类仍成立（其证据正文确有肯定表述），1 条转 `PENDING_CONFIRMED_UNSUPPORTED`。

### 1.5 E 项：三条自检绕过路径

| 检查 | 第七轮的绕过方式 | V7 处理 |
|---|---|---|
| C24 | 把 `value_raw` / `source_page` 标成 `REGISTERED_DISPLAY_ONLY` 即免审查 | 分类由 **`meta_classes.py` 按字段名锁定**，台账自报 `class` 只能被核对；放行须绑定「同键 + 同字段 + 同终值」的审查记录 `content_review_ref`。新增两个合成反例 |
| C28 | 删掉一条受限声明的逐表 ID 与总列表同一 ID、同步减小 `dispute_count` | 从 `dispute_ledger.csv` **独立重建预期引用集合**，逐表做集合相等，并要求总列表 = 四表并集 |
| C14 | 裁决依据只查 JSON 里出现过 `verdict` 字样 | 必须绑定**真实裁决文件路径 + sha256 + 具体键 + 冲突解释**；`rulings_resolved.json` 已补 `ruling_file` / `ruling_file_sha256` / `ruled_key` / `conflict_explanation` |

C35 逐表哈希本轮经第七轮确认正确，未改。

**表述修正**：C26/C29 与生产共用 `analyse()` / `required_scope()` / `parent_compatible()`，
属**同源重算**，能查台账漂移，不能证明判据本身正确。交接文本中的「改台账不改代码必被抓住」已撤回。

### 1.6 F 项：抽验补齐

- **R6** 现在交付两个父输入各自的核证结论：`parent_p1` / `parent_p2` 键、两份文档、合并范围/单位/币种、
  两份文档的重述判定、兼容性结论。不再只写「存在跨文档」。
- **R7** 新增 `locate_status`（`VERIFIED` / `WEAK` / `NOT_LOCATED`），并改定位判据为
  「最长连续原文片段 ≥20 字逐字命中」——原按整段命中率算，把多页拼接的证据误判成弱定位。
  结果：**2 条 VERIFIED + 1 条 WEAK**。C31 要求至少 1 条 VERIFIED，写 `NOT_FOUND` 不再算通过。
- **R2** 不再只挑已解除行（父输入兼容性重开后该类别已无解除行）。
- **S20/S21 自相矛盾已修**：采样表原先用 `coverage_of()` 重算覆盖，丢掉 `parent_ok` 这一维，
  出现「一边写父兼容缺失、一边保留 `RESOLVED_SCOPE_COVERED`」。现改为展示台账声明值，
  覆盖是否正确由 C29 独立重算另判。

`SH:600936|FIN.REV.SQ|20250630` 按第七轮建议处理：登记为上游核验记录异常、保留原记录与版本、
不静默覆盖；表述改为「**未定位到**」而非「原件中不存在」；该条证据的采用资格未恢复。
