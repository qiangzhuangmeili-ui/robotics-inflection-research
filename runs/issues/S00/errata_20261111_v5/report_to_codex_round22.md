## 一、四项逐条落实

### 1. `_header_cells` / `_chain_cells`：语义互补不能单独证明同列

**你构造的反例**（我复现了，生产与旁证都返回 `OK` 且第一列被认成 `本报告期（4-6月）`）：

```text
表头 y=70：本报告期 x[100,130]；（4-6月）x[134,165]
金额 y=90：100.00  x[100,130]；200.00   x[140,170]
```

**改法**：新增 `_amount_bounds(rows, ri, ax0, ax1)`（`parent_verify.py:683`），
按你说的口径——**相邻列边界**——取「本列金额与**同一行**左右相邻数字的中点」：

```python
left  = (max(左侧数字的右边界) + ax0) / 2      # 无左邻则 -inf
right = (min(右侧数字的左边界) + ax1) / 2      # 无右邻则 +inf
```

`_header_cells(rows, hdr_rows, bounds=...)` 在**合并前**比对两段的**中心**是否同侧：
`(c1 < left) != (c2 < left)` 或 `(c1 > right) != (c2 > right)` → 不合并。
`_chain_cells` 的跨行合并仍只过 `_compatible`（上下两行同一 x，不存在跨列问题）。

**没有采用你否掉的两种口径**：
- 不采用「真实财报不会这样排」的推断；
- 不采用「金额宽度 + N pt」——`_amount_bounds` 的边界由数字位置算出，**没有任何拍定的阈值**。

**为什么不用整页数字列格**（我试过，退回来了）：`_column_grid` 用右边界聚类，
在真实页面上会被脚注编号、页码切碎。`SH:603273 FIN.REV.SQ@20260630` 的 p2 页
（`DOC-…` 第 1 页）里，6 个真实列被切成 12 个簇，据此切区把 `2026` 与 `年第一季度`
判成两列，列名被削成 `年第一季度` —— 4 条真实记录从 `OK:AGREE` 变 `OK:DISAGREE`。
改回「只取金额那一行」后恢复 64/64 一致。**这是本轮唯一一次自己造出来的回归，如实报。**

**实测**（`selftest_column_rules.py`）：

```

D5 列边界取相邻数字中点       PASS  bounds=(-inf, 135.0)
D5 旁证跨列片段不得合并       PASS  merged=[(100,130,['本报告期']), (134,165,['（4-6月）'])]
C37 neighbor_fragment_not_merged = True
```

**一处必须讲清的口径差异**：该反例现在返回 `OK` + `本报告期`，**不是 `AMBIGUOUS`**。
因为 `（4-6月）` 的中心落在金额跨度之外，该金额所在列只有一个候选。
你的验收方向写的是「片段分属不同列或无法证明同列时，返回歧义／待核」——
我理解其要旨是**不得把邻列片段并进来**（上一版的错），而不是「凡邻列有片段就报歧义」。
如果你要求这种情况也报 `AMBIGUOUS`，我加一条「被列边界拒掉的片段若与本列同处一个
表头行，则整列留待核」即可，请指定。

### 2. `cols_equivalent` / `gap` / `check_c41`：堵住同侧登记凭空增加期间语义

**你构造的反例**（我复现了，`gap()` 返回 `None`、`check_c41` 返回 `[]`）：

```text
目标金额实际表头 本报告期，邻列表头 本报告期（1-6月）
登记列名写成邻列的长名称 → 生产取列得 本报告期，仍放行
```

**改法**：把两件事分开——

- `_compatible()`（片段合并）与 `cols_equivalent()`（跨文档名称互认）**保留**「空 = 不约束」，
  这正是你认可的部分（"允许缺省信息用于片段兼容"、"无需强迫 p1、p2 两份文档的列名完全一致"）；
- 新增 `_no_extra_semantics(registered, actual)`（`parent_verify.py:1035`）：**同侧**单向包含——
  登记的每个「已写」分量，实际列也必须写出来；反向（实际更详细）允许。
- `gap()` 在 `cols_equivalent` 通过后追加一条 `PARENT_COLUMN_SEMANTICS_UNPROVEN`；
  `check_c41` 在同一位置追加 `<SIDE>_COLUMN_SEMANTICS_UNPROVEN`。

**实测**：

```
D5 登记凭空加区间须被 gap 拒绝   PASS  gap='PARENT_COLUMN_SEMANTICS_UNPROVEN'
D5 登记与实际一致时 gap 不报此项 PASS  gap='PARENT_QUOTE_TOO_SHORT'（说明这一道已过）
C37 same_side_semantics_unproven = True
C37 same_side_more_detail_ok     = True   （登记 本报告期、实际 本报告期（1-6月）→ 不拒）
C41 semantics_inflation_probe = P1_COLUMN_SEMANTICS_UNPROVEN:本报告期（1-6月）⊄本报告期
```

`C41` 那一条是**合成引文探针**（`_c41_semantics_probe()`），不是逐行注入。理由：
把登记列名换成邻列长名称后，引文里本来就没有那串字，`*_QUOTE_WITHOUT_COLUMN` 会先拦住——
拦是拦住了，但证明不了新判据。合成引文把这道前置检查让开，于是唯一可能拦住它的
就是「实际列没有这段语义」。这不是放宽：`_c41` 的真实逐行重推仍是零违例。

## 三、`swap_column` 的解释更正

> **第二十三轮按裁决 3 重写本节**：上一版把两组 32 条混成一句，且有两句话不成立。
> 现行版本见 `report_to_codex_round23.md` §一.3；本节保留，但以下文字已按两组改定。

用**生产函数** `cols_equivalent(p1_column, p2_column)` 跑 64 条，结果是 **32 条不等价 / 32 条等价**。
两组必须分开说：

**（a）32 条不等价 → `swap_column` 的实际注入分母**

`2026年半年度` 对 `2026年第一季度` 18 条、`本报告期（1－6月）` 对 `2026年第一季度` 6 条、
`2026年半年度` 对 `本报告期` 4 条、`2025年半年度` 对 `2025年第一季度` 2 条、
`本期数` 对 `（1-9月）` 1 条、`本期数` 对 `2026年第一季度` 1 条。

注入方向是 `p1_column := p2_column`，也就是把 p1 的登记改成**另一份文档**的列名。
它不改变 p1 本文档金额的实际列；`check_c41` 比对的是「登记 vs **本文档**实际列」，
所以这 32 条**会被** `P1_COLUMN_MISMATCH` 拦住。

**（b）32 条等价 → 不计入分母**

`本报告期（1－6月）` 对 `本报告期` **30** 条、`本报告期（1-6月）`（ASCII 连字符）对 `本报告期`
**1** 条、`本期数` 对 `本报告期` **1** 条——即 **31 条带区间名称 + 1 条 `本期数`**。

互换后登记变成 `本报告期`，而本文档实际列本就是 `本报告期（1－6月）`：
`cols_equivalent` 判等价、`_no_extra_semantics` 也判真（登记比实际**更弱**，不是更细），
按已接受的口径（实际更详细可以放行）**按设计放行**。所以它不是「判据漏了」，
是这 32 条互换后变成了一句「更弱但不错」的话，不构成有效注入。

**撤回上一版两句错话**：

1. ~~「那 32 行两侧列名本身含区间省略」~~ → 实际是**一侧有区间、另一侧为空**的单向缺省，
   且只有 31 条带区间，另 1 条是 `本期数`。
2. ~~「互换后登记值变成了实际侧的真实列名，同侧检查不会报」~~ → 修改登记名称**不改变**
   该文档金额的实际列；带区间名称注入到短实际列时，新判据正应拒绝。

`swap_column` 仍是 32/32，分母未变——但分母是（a），不是（b）。
