## 一、先修一个把「正确登记也判死」的缺陷（F33）

`parent_verify.column_of_amount_ex()` 有两个缺陷，都会让**正确的登记**通不过：

| 缺陷 | 实测后果 |
|---|---|
| 取表头行时 `if _num_of(tx) is not None: continue`，把**年份当金额丢掉** | `2026` + `年半年度` 只剩 `年半年度`；而 `_PERIOD_COL` 要求栏目含四位年份 → `PARENT_COLUMN_NOT_PERIOD`，无论怎么登记都过不了 |
| 用金额**中心点 ±3pt** 去套表头，而数字右对齐、表头居中 | 87 条目标的 174 个父输入页面里，**97 页取不到表头**（`NO_COLUMN`），另有 52 页取到页眉标题 `…年半年度报告` |

修法（`parent_verify.column_of_amount_aligned()`，新函数，原函数保留不动）：

1. 定列改为**金额跨度与表头词重叠**（左留 20pt、右留 4pt），不再用中心点；
2. 表头行**保留年份词**；
3. 表头**跨行合并**——`本报告期` 与 `（1－6月）` 常分处两行，只取最近一行会拿到半截列名；
4. 去掉垂直距离上限，改为**排除页眉/标题行**（原上限把一页内几百 pt 处的表头挡在门外）。

效果（同一批 174 个真实页面）：`NO_COLUMN` 97 → 2，取不到表头 97 → 63（余下是真·续页）。

### 归一列名 `canon_column()`

登记侧与实际侧必须用同一把尺子，否则会出现「登记 `本报告期`、实际 `本报告期（1－6月）`，
被判不等价」这种假阴性。归一规则：有「年份+期间」取最长那段（`2026年半年度`）；
否则取最长期间词（`本报告期` / `本期数` / `年初至报告期末`）；都没有则**返回空串**
（没有期间语义的表头不能当列名）。生产侧 `_col_of()` 与自检侧同步改为返回归一值。

## 二、批次 B 做了什么

`step4_parent_scan.py`（只读扫描）→ `step4_parent_scan.csv`；`step4_apply_parents.py`
只对**两侧证据完整**的行写 `parent_verifications.csv`（27 列沿用）。

**登记页 = 证据所在页。** s00 的 `source_page` 常常是报表**续页**（该页没有表头，无法证明
「这个数是本期列」）。此时在同一文档内找「该数值与期间表头同页出现」的那一页（多为
「主要会计数据」表）。**两处数值必须逐位相等**——不相等就不登记。

| 项 | 结果 |
|---|---|
| 目标 | **87 条 / 22 家**（HOLD 中仅缺 `PARENT_COMPATIBILITY`） |
| 两侧证据齐备 | **70 条** |
| 登记为 `COMPATIBLE` | **70 条** |
| 通过完整 `gap()` 核证并闭合 | **68 条** |
| 受阻（保留待核） | **17 条** |
| `PENDING_PARENT_COMPATIBILITY` | 1,277 → **1,209** |
| 核心未闭合 | 8,674 → **8,606** |
| L2 分层 | **44 / 231 / 320 / 81 / 378（未变）** |

### 68 条闭合，但没有一家公司因此脱离 HOLD

22 家里 20 家仍在 `HOLD_PENDING_ERRATA`。原因是同批公司还卡在别的维度：
`PENDING_SCOPE_LIMITED_METHOD`（批次 A 那个「栏目不适用」的方法限制，第十七轮已否掉用它闭合）、
`UNRESOLVED_FIELD_NOT_IN_RECORD`。**父输入是必要不充分条件**，本轮不声称改善了 HOLD 家数。

### 17 条为什么保留待核

| 原因 | 条数（含重叠） |
|---|---:|
| p1（半年报侧）文档内找不到「带表头的同一数值」 | 14 |
| p2（季报侧）同上 | 9 |

具体到页：`NO_HEADER_ROW`（该页是报表续页，表头在上一页）、`AMBIGUOUS`（同一数值在同页
多行且行标签都命中）、`NO_AMOUNT`（该数值不在任何带表头的行）。逐条原因写在
`step4_parent_scan.csv` 的 `p1_note` / `p2_note`。

## 三、新增 C41：父输入登记必须能从原件重推

不信登记表自报，逐行回原件重推：绑定四元组（`security_id/field_id/period_key/ytd_field`）、
`conclusion=COMPATIBLE`、审查追溯（role/reviewer/date）、`scope_basis` 不得是空话、
口径三项须等于 s00_v10 的实际父输入、两期文档与父数须逐字相等、页码合法、
**栏目须是规范列名**、调整版本须等于 `version_used` 归类、
**引文须落在登记页且含列名+指标名+父数**、**栏目须等于该金额在原件中的实际列**。

六类注入各自被拦住（各 70 条命中，说明不是只拦首行）：

> **本节数字不实，第二十轮裁决 6 已指出**：当时 `_c41_inject()` 只改**首行**，
> `review.json` 六项各记 1；下表「70」是手写进汇报的，不是自检产物。
> 正确说法是「每类各 1 条注入、各拦住 1 条」。原文保留以便对照，勿再引用。

| 注入 | 结果 |
|---|---|
| 假引文 `营业收入100.00元` | 70 |
| 错栏目 `上年同期` | 70 |
| 错父数 `1.00` | 70 |
| 错页 `9999` | 70 |

### 本轮自己引入并已修掉的一个缺陷（如实披露）

`pdf_pages()` 在导入期就会被调用，而它逐页取词用的 `_nz()` 原先定义在文件后半段。
我把 `pdf_pages()` 前移后，`NameError` 被逐页 `try/except` 吞成「整本页面都是空串」，
表现为「原件不可用」——技术失败被写成了证据缺失。已把 `_nz()` 前移并在函数注释里写明原因；
另把「整本读取失败」不再写入缓存（一次瞬时失败会被永久记住）。

同时修正 C37 的一处**假阳性**：判「有无自动捷径」原先用**带登记表**的结果去试，
登记一多，70 条真实核证会被报成捷径。现改为用**空登记表**去试。

## 四、请复核时重点看的四点

1. **登记页可以是「主要会计数据」页，而不是 s00 的 `source_page`。** 理由是续页无表头；
   两处数值逐位相等才登记。这是否可接受？若不接受，请给出替代口径——按现口径
   87 条里只有 3 条能靠续页本身证明列身份。
2. **`canon_column()` 归一**（`本报告期（1－6月）` → `本报告期`）是否算放松？
   它只把两侧写成同一形式，不改变「哪一列」；跨列仍会被 `_PERIOD_COL` 与
   `cols_equivalent` 拦住（C37 的 11 组异义用例仍在跑）。
3. **把 `_col_of()` 从中心点改成跨度重叠**是否可接受？这是修 F33，不是放松：
   实测同一批页面 `NO_COLUMN` 97 → 2，且 C37 的「错栏目必须被拒」用例仍全部命中。
4. **C41 与 `gap()` 共用同一个取列函数**，存在「同源」风险。C41 的独立部分是：
   引文内容（列名+指标名+父数）、页码定位、版本标记、口径三项、依据文字——
   这五项不依赖取列函数。是否还需要一条完全不依赖 `column_of_amount_aligned()` 的旁证？
