## 二、第 1 步：判据怎么换的

### 2.1 不再用期间相等

V5 把「证据覆盖了什么」和「这行需要什么」分开算，差集写进 `scope_missing`：

- `coverage_of(rec)`：从证据正文抽 `ERRATA` / `MERGER_RETRO` / `POLICY_CHANGE` / `QUANTIFIED`，不看方法名。
- `required_scope(status, own_period)`：
  - 非自身期间 → `ERRATA + MERGER_RETRO + COMPARATIVE_SCOPE`
  - `EXTRACTED_QUARTERLY_TABLE` → `ERRATA + QUARTERLY_TABLE_PROVENANCE`
  - 其余 → `ERRATA`

一个直接后果：`NOTE_RETAINED_ERRATA_ZERO` 的正文是「重大会计差错更正影响期初未分配利润 0.00 元；同一控制合并范围变更 0.00 元」，它其实覆盖 `ERRATA + MERGER_RETRO`，比方法名看起来强。裁决要求它不得整体计作已闭合——V5 照办（仍转待核），但在分组里把它单列为**优先复核组**，因为它的证据质量确实高于 `IMPORTANT_MATTER_NA`。

### 2.1b 新增 `RESOLVED_RESTATEMENT_CONFIRMED`

`NOTE_RETAINED_ERRATA_NONZERO`（8 条，`*ST九鼎`、`派斯林`）披露的是**非零**差错更正（影响期初未分配利润 −160,517.06 / −1,307,267.41 元）。V4 把这类一律记 `UNRESOLVED_EVIDENCE_MISMATCH`，但它们其实是证据与 B **一致**的：B 判 `是`，证据也说有更正。V5 改为：

- B=是 → `RESOLVED_RESTATEMENT_CONFIRMED`（证据确认了 B 的「是」）
- B=否 → `UNRESOLVED_EVIDENCE_CONTRADICTS`（真冲突）

这条分支由 C14/C17 校验，且 C26 会跳过（它不是「未被重述」断言，而是「已重述」断言）。

### 2.2 5,270 条的数字对上了

`PENDING_SCOPE_LIMITED_METHOD` 共 6,373 条，分解：

- **自身期间 5,270 条**（与裁决复算完全一致）
- 非自身期间 1,103 条（V4 本就待核）

### 2.3 没给累计差分行加 MERGER_RETRO

裁决第三节提到「报告自身期间的单季值也可能由本期和前季累计值差分」。我考虑过给 `DERIVED_CUMULATIVE_DIFF` 行追加 `MERGER_RETRO` 必需项，但这样会把「同一份报告内 YTD 相减」也判成证据不足——同一份报告的两个父输入受同一次追溯调整影响，差分后相互抵消。真正的风险是父输入是否可信，属于依赖引擎的职责。

所以改成：证据侧只要求 `ERRATA`，依赖侧由 `l2_core` 把 YTD(t)/YTD(t−1q) 纳入依赖集合，第 4 步再逐条核父键闭合。若您认为仍应在证据侧要求 `MERGER_RETRO`，请裁定，我可以单开一个 `PENDING_CAUSE_UNCOVERED` 变体（当前该标签只有 29 条）。

### 2.4 依赖引擎读实际行状态

`l2_core.expand()` 按 B 的 `status` 分支：

| status | 展开 |
|---|---|
| `EXTRACTED_QUARTERLY_TABLE` | 只依赖自身 |
| `DERIVED_Q1_EQUALS_YTD` 或日历 Q1 | 加 YTD(t)，不减上年年末 |
| `DERIVED_CUMULATIVE_DIFF` | 加 YTD(t) 与 YTD(t−1q) |
| 状态未知 | 并集（仅自检用） |

裁决点名的例子：

```
dependency_keys("M07", "20260630")
→ 现含 FIN.NPDEDT.YTD@20250331   （V4 缺）
```

裁决提到的三家（工业富联 `SH:601138`、石头科技 `SH:688169`、比亚迪 `SZ:002594`）：工业富联与比亚迪现落在 `HOLD_PENDING_ERRATA`，石头科技不在 HOLD。分层数量从 331/77/37 变为 330/72/43，但**如您所说，数量变化不能证明依赖完整**，这里只是如实报告。
