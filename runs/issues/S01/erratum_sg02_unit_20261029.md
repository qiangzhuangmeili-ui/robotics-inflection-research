# S01 勘误：SG02 阈值单位矛盾（v1 → v2）

- 发现于：Codex 复验提交 `522e1cd`（2026-10-29）
- 性质：**既存定义错误**，不是本轮执行者调整阈值；文字定义从未变，是机器阈值与文字不一致
- 处置：v1 原冻结文件**保留不改**，新建 `screen_rules_v2.json` 只改这一处

## 一、问题

| 位置 | 内容 | 单位 |
|---|---|---|
| `metric_formulas.md` | SG02 =「M03 ≥ **5pp**」 | pp |
| `threshold_rationale.md` | T2 =「单季加速 ≥ **5pp**」 | pp |
| `screen_rules_v1.json` | `threshold: 0.05`, `unit: "pp"` | **0.05pp**（错） |
| `s01_rules_check.py`（R2 及以前） | `M03 >= 0.05`，M03 已 `×100` 为 pp | **0.05pp**（错） |

M03 的返回值是 `(本季同比 − 上季同比) × 100`，单位是百分点；再拿 0.05 去比，等于要求「加速 0.05 个百分点」，比文字定义小 100 倍。

补测证据：M03 = 1pp 即触发 SG02；全池干跑有 **107 条** SG02 触发的加速度低于 5pp（522 − 107 = 415）。

## 二、处置

| 文件 | 状态 |
|---|---|
| `screen_rules_v1.json` | **原样保留**，sha256 `c76d0461…`，与 `326ecac` 提交逐字节一致（机器校验 C14） |
| `screen_rules_v2.json` | 新建，`rules_version=S01_SCREEN_RULES_V2`，只改 `signals[SG02].threshold` 0.05 → **5.0**（单位仍 pp）并更新 note；新增 `change_log` 记录来源 |

v1 → v2 的完整差异（机器枚举，C15）：

```
change_log
frozen_at
rules_version
signals[1].note
signals[1].threshold        # SG02：0.05 → 5.0
```

**没有其他字段变化**，指标、其他信号、策略、指纹全部照旧。

这些数字只用于证明定义一致后的可执行性，**不是名单，也不用于反推门槛**。SG02 命中减少是单位修正的算术后果（5pp > 0.05pp），不是按命中率调参。

## 四、为什么不是「直接改 v1」

`screen_rules_v1.json` 的 `change_procedure` 明定：v1 冻结后只读，任何修改以新版本文件体现。直接改 v1 会让此前所有基于 v1 的复算失去可追溯性，也无法向复核方证明「只改了单位」。

## 五、影响

- S01 自身：规则引用改指 v2，自检与干跑按 v2 重算
- S02 及以后：一律使用 v2；若将来要改阈值（不只是单位），仍须新建 v3 并全池重算
- 历史结论：此前任何引用「SG02 命中 522」的说法，都应注明是 v1（0.05pp）口径，已作废
