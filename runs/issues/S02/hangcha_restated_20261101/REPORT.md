## 三、P01：字段目录行数（交接方案的数字本身也是错的）

### 3.1 根因比交接说明更深

`science_rules_match()` 把整个 `field_catalog` 当科学规则比对，而 `field_catalog[*].rows` 是**随输入变化的实测行数**。更关键的是：

| 事实 | 数值 |
|---|---|
| 冻结目录 `FIN.NPDEDT.YTD.rows` | 18,018（基于原始 S00，228,155 行） |
| S00 v9 实际行数 | **18,112** |
| 交接 patch 改成的值 | 18,019（= 18,018 + 1） |
| v10 实际行数 | **18,113** |

即：冻结目录相对 v9 已经**全部 17 个字段**都不一致（例如 `FIN.REV.YTD` 声明 13,308、实际 13,404），S02 过去从未校验过这件事。交接方案按"原值 +1"改成 18,019，既通不过 P01，数字本身也不对。

### 3.2 修复方式

1. `s02_calculate.py`：把 `rows` 列为 `DYNAMIC_CATALOG_KEYS`，科学规则比对时剔除；其余字段定义（名称、口径、期间）仍逐项严格比对。
2. 新增审计块 `field_catalog_row_counts`：必须逐字段登记 `frozen_rows` / `current_rows`，并给出 `reason` 与 `input_version`；审计块与实际变化不一致即 FAIL。
3. 新增阻断检查 **P07**：字段目录声明值必须等于本次输入实测行数（17 个字段逐项核）。
4. `apply_hangcha_restated_patch.py`：删除硬编码 18018/18019，改为从 v10 实际行数逐字段重算（本次 17 个字段全部更新）。
